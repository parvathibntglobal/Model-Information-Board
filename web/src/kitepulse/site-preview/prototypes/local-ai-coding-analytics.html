Why a solo developer wants their own AI coding stats

When you work alone, nobody asks for a usage report. The questions come from you. Which client project took most of last month's AI work? Is your Claude plan the right size, or do you hit the weekly window every Thursday? Did the new model you switched to change how you work?

The raw answers already sit on your disk. Claude Code, Codex, Cursor and the other assistants each keep a history of every session. What is missing is one place that reads all of it the same way, links each session to its project, and shows the result over weeks. That is what "my AI coding stats" means in practice: your own figures, from your own history, across every tool you use.

Four ways to get personal Claude Code usage stats

There is more than one way to get personal Claude Code usage stats, and the right one depends on how many tools you use and where you are willing to send your session history.

Built in

Each tool's own usage screen

No setup and nothing new to trust. Each covers a single tool and shows what that vendor chooses, usually without your projects or a month-to-month history.

Do it yourself

Scripts over local logs

Private and free to write. Every tool keeps its history in its own format, and the formats change, so a script that covers several tools becomes a small project you maintain.

Hosted

A vendor-hosted analytics service

Nothing to run. Your session history, which can include code the AI read or wrote, goes to someone else's servers, which a client contract may not allow.

Self-hosted

Analytics on your own computer

Several tools in one consistent view, and the data stays on your machine. You run the software yourself, which means installing it, starting it and keeping it updated.

If one tool's own screen answers your questions, stay there. Self-hosting earns its place when you use several assistants, work for several clients, or cannot send session content off your machine.

Self-hosted Claude Code analytics on one computer

Every way of running Kite Pulse is self-hosted. The smallest is one computer for one person: a single command sets up the server, the background worker, the collector (the desktop program that reads your AI tools' history) and the database, all on your machine and reachable from that computer only. The full list of ways to run it, from this up to an Ubuntu server or your own AWS account, is on the self-hosted deployment page.

From install to first figures:

  1. Run the install command. The first start takes a few minutes and ends by printing the address of your console.
  2. Open that address and sign in as the first admin. You are asked to choose a new password straight away.
  3. Confirm your projects in the Onboarding Wizard. The collector has already found your project folders and their repository addresses, but no session content is sent until you confirm. Approval of a first project list is on by default; on a solo install you can switch it off in Detection Rules. An empty console before this step is expected.
  4. Keep working. The collector runs in the background, reads the history each tool already keeps, masks secrets and sends only new activity.

It reads ten tools out of the box: Claude Code, Codex, Gemini CLI, Cursor, GitHub Copilot Chat in VS Code, Cline, Roo Code, Kilo Code, OpenCode and Aider. You can switch any of them off, or collect token counts only, so the numbers are counted without the conversation being stored.

Your personal pages are the same ones every team member gets, and our page for individual developers walks through them: Workspace with each project's collection status and your Claude plan usage, My Activity, My Sessions, My Scorecard & Insights with its "Top 3 to act on", work-pattern facts, working style and private prompt statistics.

The difference on a one-person install is that you are also the admin, so pages a developer on a team does not see by default are yours too:

  • Team AI Usage shows your token use per tool, model, project and day, for any period. Its Models tab shows which models you used and how that changed over time, and Plan headroom shows how close you are to your Claude plan's 5-hour, weekly and per-model weekly windows.

For a freelancer, a project is often a client, so this is a simple way to notice when one client's work is running hot. Our post on AI cost per project covers how to read those figures.
  • The company report covers any period against the previous one and downloads as CSV or PDF, which makes a tidy monthly record of your own work.

Self-hosted AI usage tracking: where your data goes

Self-hosted AI usage tracking only means something if you can say exactly where the data goes. On a one-person install, the answer is short: from the collector to the server on the same computer, with no vendor cloud in between. The collector will not run until it is given a server address, and none is built in.

The usual safeguards still apply locally. Secrets matching 36 credential patterns are masked on the computer before upload and again on the server before storage. Session uploads are encrypted before they leave the collector. The collector reads session records, folder names and repository addresses, and does not open your source files, log keystrokes, take screenshots or track websites; session records can still include excerpts of code the AI read or wrote. The full list is on the privacy page.

One switch can send text outside: AI labelling. It is off until an admin sets it up with an OpenRouter key and a monthly budget, and if you turn it on, scrubbed text goes to the AI provider through OpenRouter. On a solo install that admin is you, so the decision is yours.

An illustrative example: one freelancer, two clients

Illustrative example, not a customer case

A freelance developer uses Claude Code for most work and Cline for one client who asked for it. Both clients' repositories live on the same laptop. After installing on that laptop and confirming both projects, she checks Team AI Usage at the end of the month. The Projects tab shows which client took more of her tokens, the Claude Code cost estimate sits beside Cline's own reported cost, and Plan headroom shows which weeks she ran close to her weekly window. She sets a monthly token budget on the busier project so the 80% alert tells her early next time.

None of the session history left the laptop. The cost figures are estimates, not an invoice, and the two tools' costs are shown side by side, never added up.

Questions about running it alone

Can one person use Kite Pulse alone?

Yes. One command sets up the server, background worker, collector and database on one computer, reachable from that computer only. You get the same personal pages a team member gets, and because you are the only admin on that install, you also see the usage, cost estimate and plan pages for your own work.

Does Kite Pulse send data to a vendor's cloud?

No. Session data goes only to the server you run, and on a one-person install that server is on the same computer. It works without any AI service; if you choose to switch on AI labelling, scrubbed text is sent to the AI provider through OpenRouter, and that is off until an admin sets it up.

Is there a self-hosted tool to monitor AI coding tool usage?

Yes. Kite Pulse reads the session history of ten AI coding tools and keeps it on a server you run, from one computer up to an Ubuntu server or your own AWS account. It covers Claude Code, Codex, Gemini CLI, Cursor, GitHub Copilot Chat in VS Code, Cline, Roo Code, Kilo Code, OpenCode and Aider, and no other tools.
