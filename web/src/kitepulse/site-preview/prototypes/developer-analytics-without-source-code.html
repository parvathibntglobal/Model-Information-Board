Developer Analytics Without Source Code Access: Privacy Developers Can Check

Kite Pulse teamUpdated 30 Oct 20268 min read

Developer analytics without source code access means measuring AI-assisted work from the session history the AI tools already keep, without opening project files, logging keystrokes or taking screenshots. There is one caveat to state plainly: session records can include excerpts of code the AI read or wrote, with secrets masked.

Developers accept a tool like this when they can check what it collects for themselves. That acceptance is what keeps the figures complete, because nothing uploads until each developer has confirmed their projects.

Why developer buy-in decides whether the figures are complete

For AI usage data, privacy is a data quality question as much as a legal one. A tool that reads AI coding sessions only sees the projects a developer agrees to share. If people hold back, the figures still arrive, but they describe part of the team and look like all of it.

In Kite Pulse this is built into the order of events. No session content uploads until the developer confirms their projects in the Onboarding Wizard and, where your organisation requires it, an approver signs off. Before that, the only thing sent is the list of detected project folders (paths, names and repository addresses), so the wizard can show it. A developer who does not trust the tool can leave a project unconfirmed, and that project stays out of every report.

The practical test for HR, a works council or a leadership team: can a developer see, on their own screen, what is collected and who will read it? If not, expect gaps nobody can explain later.

What "without source code access" means, exactly

The phrase is easy to overstate, so it helps to separate what is read from what is never opened.

What the desktop program reads

  • The session history ten AI coding tools already keep on the computer
  • Folder names and repository addresses, so one repository cloned on several machines counts as one project
  • Token counts and plan figures the tools save themselves

What it does not do

  • Open a project's source files
  • Log keystrokes or take screenshots
  • Track websites
  • Send anything to a vendor cloud

The caveat to put in writing: session records can include excerpts of code the AI read or wrote, because that is what an AI coding conversation contains. Those excerpts travel with the session, with secrets masked. An agreement that says "no code leaves the developer's computer" is not accurate for full session sync; say so on day one.

Some extra reads, such as the branch name, package manifests and project notes like README files, are off until an admin turns them on. List in your agreement which of these, if any, you plan to switch on.

Privacy preserving analytics: safeguards a developer can verify

Privacy preserving analytics works best when each safeguard is something a developer can look at in the product, not only a clause in a policy. Kite Pulse provides these:

  1. Consent before sync. In the Onboarding Wizard a developer reviews the projects found on their computer, fixes, adds or removes them, and only then starts syncing. An approver confirms the first project list where your organisation keeps approval switched on.

  2. A Privacy page for every person. Each person sees every data point recorded about them, whether it is on now, and who can see it: themselves, their manager or admins.

  3. Private fields stay private. Prompt statistics, such as a person's most repeated prompt and reply pace, are shown only to that person; the server removes them for everyone else. Managers who do not work on a project see folder labels, not full paths.

  4. Scope enforced by the server. A developer sees their own pages, a manager sees their reporting line, and an admin sees everyone. The server enforces this, not just the screen.

  5. Pseudonymised tool accounts. For the AI tools' own accounts, only a keyed hash of the account, the email domain and the plan name are sent by default, never the address.

For a wider discussion of where the ethical lines sit, see our guide to tracking AI usage ethically. The full list of what is read, why and what is sent is on the Kite Pulse privacy page.

Secret masking, on the computer and again on the server

Because session records can contain excerpts of code and pasted text, they can also contain credentials. Secret masking happens twice:

  • On the developer's computer, before upload. 36 credential patterns are masked, including cloud and AI provider keys, GitHub and GitLab tokens, private keys, and passwords in URLs or labelled fields. If masking fails, that part is not sent.
  • Cursor and OpenCode. These tools' login stores are never sent. Credentials pasted into their chats are masked on your server only.
  • On the server, before storage. Every session is masked a second time.

Session uploads are encrypted on the computer before they leave, and small status records go over HTTPS, only to your team's own server. Protecting stored data on that server's disks is part of running it, so include it in your own security review.

Track token usage without collecting prompts

Not every question needs the conversation. Kite Pulse has two switches per tool on the Tools page: Session sync, which uploads the conversations, and Token consumption, which counts tokens. With Session sync off and Token consumption on, the program counts tokens on the computer and sends only the numbers, never the conversation.

Put the trade to the works council in those terms. Counts-only mode gives usage figures per tool with no prompt text leaving the computer. Full session sync gives the session views and work patterns, and uploads the conversation, including any code excerpts, with secrets masked. You choose per tool, and can start with counts only and widen it later by agreement.

When this approach is not the right fit

  • You need delivery metrics. For DORA metrics from git and tickets, a git or ticket based analytics tool fits better.
  • No code excerpt may leave the computer. Full session sync does not meet that rule. Counts-only mode does, with token figures only.
  • You need to cover tools outside the ten. Kite Pulse reads Claude Code, Codex, Gemini CLI, Cursor, GitHub Copilot Chat in VS Code, Cline, Roo Code, Kilo Code, OpenCode and Aider, and nothing else.

Questions from HR, works councils and leaders

How do I track AI usage without making developers feel monitored?

Collect only what the questions you are answering need, and let developers check it. Read the AI tools' own session records instead of screens or keystrokes, ask each developer to confirm their projects before anything uploads, and give every person a page that shows what is recorded about them and who can see it. Where you only need volume, collect token counts without the conversations.

How do I explain AI usage tracking to my team?

Explain it in four plain statements: what is read, what is not read, who can see which parts, and how each person checks it for themselves. Be exact about the caveat: session records can include excerpts of code the AI read or wrote, with secrets masked. Then show people their own Privacy page before the first upload, so the explanation can be checked.

Will developers see AI usage tracking as surveillance?

Some may, and a vendor cannot promise otherwise. It depends on what is collected, who sees it and what it is used for, which your organisation decides. Kite Pulse does not log keystrokes, take screenshots or track websites, asks for consent before sync and shows each person their own data, but the agreement on how the figures are used is yours to make with HR and the works council.

How are secrets and credentials handled before upload?

On the developer's computer, 36 credential patterns are masked before upload, including cloud and AI provider keys, GitHub and GitLab tokens, private keys and passwords in URLs or labelled fields. If masking fails, that part is not sent. For Cursor and OpenCode chat text, masking happens on the server, and those tools' login stores are never sent. Every session is masked a second time on the server before storage, and uploads are encrypted in transit.
