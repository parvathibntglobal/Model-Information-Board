Why agencies ask about AI cost per project

An agency sells time and outcomes per client. When most of a developer's day runs through an AI coding assistant, a large part of the effort on each engagement now happens inside those conversations. The vendor bills arrive per tool or per seat, though, and they say nothing about which client the work was for.

Delivery leads end up asking questions the bills cannot answer. Which engagements lean hardest on AI? Is a fixed-price project using far more AI effort than the team scoped? Are people working on client code with a personal AI account? This article walks through what Kite Pulse can show for each of those, and where it stops.

AI coding spend by project starts with tokens

Kite Pulse's desktop program reads the session history that ten AI coding tools already keep on each developer's computer. It finds project folders and reads each repository's address, so one client repository cloned on several laptops counts as one project, and every session is linked to its project. Nobody fills in a timesheet or tags a session by hand.

On Team AI Usage, token use is shown per developer, tool, model, project and day, for any period you pick. The Projects tab is the per-engagement view: which client projects used the most AI effort this month or this quarter. The Models tab shows models by project, which is useful when one client's work runs on a more expensive model than another's.

Cost sits one step further back. Kite Pulse estimates cost by multiplying tokens by each vendor's published list price, and labels it "not billed spend". Claude and Gemini models are priced, and Aider, Cline, Roo Code, Kilo Code and OpenCode report their own cost. Codex, Cursor and Copilot sessions usually show a dash, never $0. On Team AI Usage, cost is shown per tool and never added up across tools. Our guide to tracking AI coding cost explains why list-price estimates and subscription bills differ.

A monthly AI budget per project

The only place Kite Pulse puts a dollar figure against a project is AI Budgets. An admin sets a monthly budget for a project, or for a team, in tokens or in estimated US dollars. Each budget shows what was used this month, a bar and a status, and raises an alert at 80% and again at 100%.

A dollar budget adds up the priced tools only. Tokens from tools with no known price are reported separately, never counted as $0, so a project where most work runs on Codex or Cursor shows that gap openly. For those projects a token budget is usually the more honest choice.

For an agency, a monthly AI budget per project works well as an early warning on fixed-price work. If a client engagement crosses 80% halfway through the month, the alert arrives while there is still time to talk about scope. See how AI budgets work for the setup.

Billable AI usage for clients: what Kite Pulse does not do

Many agencies search for a way to show billable AI usage for clients. Kite Pulse is not that tool, and it is worth being plain about why.

  • The figures are estimates. Cost comes from list prices, while many developers are on flat subscriptions. The estimate can sit far from what the agency actually paid.
  • Coverage is partial. Several tools usually show no price, so any dollar figure leaves part of the work out.
  • There is no invoice view. Nothing in the console produces a client invoice or a billable figure.

If you bill clients for AI usage or for hours, your vendors' invoices and your time-tracking or billing system remain the source of record. What Kite Pulse adds is the picture behind them: which engagement the AI effort went into, which tools and models it used, and how that compares with last month. That is useful in a scoping conversation or a project review, and it is not a line on an invoice.

Personal AI accounts used for client work

Client contracts often say where client code may go. A developer who signs in to an AI tool with a personal account on a client project is a question a delivery lead wants to see early.

Tool Accounts counts how many separate signed-in accounts each tool runs under and marks any account used by more than one person as "Shared". It shows plan tier, machines, last seen and email domain, so an account on a personal email domain stands out next to company ones. It covers Claude Code, Codex, Cursor, OpenCode and GitHub Copilot, and is admin by default. Accounts are pseudonymised: Kite Pulse receives a keyed hash of the account, the email domain and the plan name, never the address.

Kite Pulse's view of unapproved AI use rests on two partial signals only. The first is Tool Accounts: the "Shared" flag for five tools and email domains for four (not Copilot). The second is an optional read, off by default, that lists which of six known AI tools are installed on each machine. Neither finds AI tools outside that list or tools the organisation has not switched on.

Jira issues linked to AI coding sessions: a project-level link

Many agencies run each client in its own Jira project, and often track the client relationship in HubSpot. On the Connectors page an admin can connect Jira, HubSpot, Slack, GitHub, Confluence, Google Drive and Notion and map each one to a Kite Pulse project. Connector credentials are stored encrypted.

Keep expectations at the project level. Sessions belong to a project, and the client's Jira project or HubSpot company can be mapped to that same project. Kite Pulse does not give you AI cost per ticket. If you need time per issue, your ticket tracker or a time-tracking tool is the better source, and Kite Pulse can sit beside it as the record of how the AI part of the work went.

A monthly routine for delivery leads

A simple loop that fits most agencies, using only what is described above:

  1. Check the project list. On All Projects, make sure each client repository is one project, with its health, sessions, contributors and last activity. Duplicate Detection offers to merge folders that are the same repository.

  2. Set budgets for fixed-price work. Give each fixed-price engagement a monthly AI budget, in tokens where most of its work runs on unpriced tools.

  3. Review usage per engagement. At month end, open Team AI Usage for the month and compare token use per project with the month before.

  4. Check accounts. Look at Tool Accounts for shared logins and personal email domains on client work.

  5. Share the picture. Download the Company report for the period as CSV or PDF, or schedule it by email daily, weekly or monthly.

Questions agencies ask

Can we track AI spend per project for client billing?

Not for billing. Kite Pulse does not produce invoices or billable figures. It shows token use per project for any period, and an estimated dollar figure per project only through an AI Budget, month to date, at list prices and for priced tools only. Use it to understand effort per engagement, and use your AI vendors' invoices for what you actually paid.

Can I track AI coding costs by developer, team, department, and project?

Partly. Token use is shown per developer, tool, model, project and day. Estimated cost is shown per tool, cost per developer is visible to admins only on that developer's AI Usage tab, and cost per team or per project appears only in AI Budgets, month to date. There is no separate department level: budgets are set per team or per project.

How do I find out which projects my team uses AI on the most?

Open Team AI Usage, pick the period, and use the Projects tab: it shows token use per project, and the Models tab shows which models each project relies on. All Projects adds sessions, contributors and last activity for each project. Managers see their own reporting line; admins see everyone.
