Why terminal agents are hard to see from outside

Codex and Gemini CLI run in a developer's terminal. They read files, run commands, propose edits and loop until the task is done or the developer stops them. The work that matters, the back and forth, the retries and the tokens spent, lives inside those sessions. A pull request shows the result. It does not show which agent did the work, how many tokens it took or whether the same command failed five times on the way.

Both tools write that history to the developer's own computer. On its own, each history is one person's record on one machine. For a team lead, the question is what the whole team looks like: who uses which agent, on which projects, with which models, and at what estimated cost.

Captured without extra steps

Kite Pulse puts a small desktop program on each developer's Windows or macOS computer. It reads the history each tool already keeps, in the Codex and Gemini folders in the developer's home directory, and it follows CODEX_HOME if a developer has moved their Codex history elsewhere. Nobody logs anything by hand, and nobody changes how they start a session.

  • Only new activity is sent. Codex and Gemini CLI histories are files that grow as the session runs, so the program resumes from the last point your server already has.
  • Nothing lost offline. If the network drops, the program remembers where it stopped and catches up once the server is reachable.
  • Projects found automatically. Each session is linked to its project by folder and repository address, so one repository cloned on several machines counts as one project.
  • Consent first. No session content is uploaded until the developer confirms their projects in the Onboarding Wizard and, where required, an approver signs off.

Both tools are on in a new install, alongside the other eight that Kite Pulse reads. An admin can switch either one off on the Tools page, or switch off Session sync and keep Token consumption on. In that counts-only mode the program counts tokens on the computer and sends only the numbers, never the conversation.

Codex CLI token usage and Gemini CLI token usage on Team AI Usage

Both agents report tokens in full, so Codex CLI token usage and Gemini CLI token usage sit on the same Team AI Usage page as every other tool. You can break token use down per developer, tool, model, project and day, for any period. Managers see their own reporting line; admins see everyone.

The Models tab answers the questions a team asks once more than one agent is in play: how many developers use each model, how model adoption changes over time, and which models each project relies on. Because Codex and Gemini CLI both record the model name on every session, their models appear there next to the rest.

This is where Gemini CLI team usage and Codex usage become comparable. A lead can see that one project runs mostly on Gemini CLI while another has moved to Codex, without asking anyone to fill in a form.

Gemini CLI cost, and why Codex shows a dash

Gemini CLI cost is an estimate. Kite Pulse multiplies each session's tokens by the vendor's published list price for that Gemini model. When a price changes, the new price is added as a dated entry, so older sessions keep the price they ran at. The figure is labelled "not billed spend": many developers are on flat subscriptions and do not pay per token, and your invoice is the record of what was charged.

Codex is different. Kite Pulse has no list price for OpenAI models, so Codex sessions show a dash in the cost column, never $0. A zero would read as "free", and that would be wrong. The tokens are all there; only the price is missing.

On Team AI Usage, cost is shown per tool and never added up across tools, so a Gemini CLI estimate is never mixed with a Codex blank. Cost per developer is shown to admins only.

Budgets with one priced tool and one unpriced

Admins can set a monthly AI budget per team or per project, in tokens or in estimated US dollars, with alerts at 80% and 100%. A dollar budget adds up the priced tools, which includes Gemini CLI, and reports unpriced tokens, such as Codex tokens, separately. If your team uses Codex heavily, a token budget may be the clearer choice, because it counts every Codex token.

Codex accounts and ChatGPT plans on Tool Accounts

Tool Accounts counts how many separate signed-in accounts each tool runs under. For Codex it shows each account with its ChatGPT plan, plus the machines it was seen on, when it was last seen and its email domain. An account used by more than one person is marked "Shared", which shows where one login is being passed between people.

Accounts are pseudonymised by default. The program sends a keyed hash of the account, the email domain and the plan name, never the email address. Tool Accounts is an admin page by default.

Gemini CLI has no entry here. Kite Pulse deliberately does not read Gemini CLI account or plan details, so it cannot tell you which Google account a session ran under or which plan it used.

Plan limits: what this view does not cover

If your main worry is developers running out of allowance mid-task, be clear about scope. Plan headroom in Kite Pulse covers Claude Code only: the 5-hour window, the weekly window and each model's weekly window, with "near" at 80% or more and "at limit" at 100%. For Codex and Gemini CLI, that view says "Not reported by this tool".

For their limits, each vendor's own account pages are the source. What Kite Pulse adds is the usage side: who is spending tokens with which agent, on which project, and how that changes week to week. If you only need one vendor's limits for one tool, that vendor's console fits the job better.

Questions about Codex and Gemini CLI usage

How do Codex usage limits work?

OpenAI sets Codex usage limits, and its own documentation is the place to read how they are counted for your plan. Kite Pulse does not read Codex limits: its Plan headroom view covers Claude Code only, and Codex shows "Not reported by this tool". What Kite Pulse does show for Codex is token use per developer, model and project, and the ChatGPT plan each Codex account runs under on Tool Accounts.

Does Gemini CLI have usage limits?

Google sets the limits for Gemini CLI, so check Google's own documentation for your setup. Kite Pulse does not read Gemini CLI account or plan details at all, so it cannot tell you how close anyone is to a Gemini limit. It does show Gemini CLI tokens, models and an estimated cost from list prices.

Does Kite Pulse show a cost for Codex?

No. Kite Pulse has no list price for OpenAI models, so Codex cost shows a dash, never $0. Codex token counts are still shown in full, and a dollar AI budget reports those unpriced tokens separately instead of leaving them out silently.
