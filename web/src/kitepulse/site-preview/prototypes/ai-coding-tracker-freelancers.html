Why a solo developer wants a record of AI-assisted work

Working alone, you are your own manager, finance team and IT department. You probably use more than one assistant, say a terminal agent for larger changes and an editor extension for quick questions, and you move between projects for different people in the same week.

Each AI tool keeps its own history on your computer, in its own format. None of them tells you how your week split across projects, which tool did the heavy lifting on which repository, or whether your Claude plan's 5-hour window will run out before a deadline. For that you need one record that reads all of them the same way.

And your sessions contain other people's code, so a tracker that uploads them elsewhere adds a party to every engagement.

Self-hosted AI usage tracking on one computer

Kite Pulse is always self-hosted, and its smallest form is a single machine. One command sets up the server, the background worker, the desktop program and the database on your computer, reachable from that computer only. Getting started alone takes four steps:

One record across tools and projects

The desktop program reads ten AI coding tools out of the box: Claude Code, Codex, Gemini CLI, Cursor, GitHub Copilot Chat in VS Code, Cline, Roo Code, Kilo Code, OpenCode and Aider. It runs in the background with nothing to log by hand. The integrations page lists what each tool provides, since they do not all record the same detail.

To track AI coding tool usage per engagement, each session has to land in the right project. The program finds project folders and reads each repository's address, so a repository cloned twice still counts as one project. On My Projects you can confirm, rename, split or remove a project, and the Projects tab of Team AI Usage shows token use per project for any period.

You decide what is read. Any tool can be switched off, or set to counts only, where only token numbers are sent, never the conversation. A project that is switched off is not read at all.

Claude Code for freelancers: watching your own plan

If Claude Code is your main tool, its usage windows shape your working day. Workspace shows your Claude plan usage, read from the figures Claude Code saves on your computer. Plan headroom covers the 5-hour window, the weekly window and each model's weekly window, marking "near" at 80% or more and "at limit" at 100%, with old readings flagged as stale. By default the figures are as fresh as Claude Code's last save; an optional background refresh keeps them current without using any tokens.

Over a longer stretch, the Plan usage report shows weekly peaks, weeks at 80% or more and windows at the limit for a month or a date range, as an Excel download: a sound basis for deciding whether your plan still fits. Plan limits are read for Claude Code only; other tools show "Not reported by this tool". Our guide to Claude Code usage limits explains the windows themselves.

Estimated cost, and what it is not

Cost is an estimate, tokens times the vendor's published list price, labelled "not billed spend". On a flat subscription it can sit far from what you paid. Claude and Gemini models are priced, and Aider, Cline, Roo Code, Kilo Code and OpenCode report their own cost. Codex, Cursor and Copilot sessions usually show a dash, never $0. Team AI Usage shows cost per tool and never adds it up across tools.

For an early warning per project, AI Budgets sets a monthly budget in tokens or estimated US dollars, with alerts at 80% and 100%. A dollar budget adds up priced tools only and reports unpriced tokens separately, so for work mostly on Codex or Cursor a token budget is the honest choice.

None of this is an invoice. There is no billing view, and the estimates are not a figure to pass on to anyone you work for; your vendors' invoices remain the record. How AI coding cost tracking works explains why estimates and subscription bills differ.

Is this time tracking for software developers?

Not in the timesheet sense. My Activity shows when, for how long and with which tools you worked, which tells you where AI-assisted time went. It does not record billable hours, and a call or an hour of reading documentation leaves no trace in it. If you bill by the hour, keep your time tracker; an AI coding record sits beside it as the account of how the AI part of each project went.

Questions freelancers ask

Can one person use Kite Pulse alone?

Yes. One command sets up the server, background worker, desktop program and database on one computer, reachable from that computer only. You get the same personal pages a team member gets, and because you run the install you also see its admin pages, such as Team AI Usage and AI Budgets.

Does Kite Pulse send data to a vendor's cloud?

No. Data goes only to the server you run, and on a one-computer install that server is your own machine. There is no vendor cloud in between. The one exception is optional: if you turn on AI labelling, which is off by default, scrubbed text is sent to the AI provider through OpenRouter, with a default policy of zero data retention.

Does Kite Pulse read my source code?

It does not open your project source files. It reads the session history your AI coding tools keep, plus folder names and repository addresses. Those session records can include excerpts of code the AI read or wrote, and secrets in them are masked on your computer and again on the server.
