What an AI coding analytics platform is for

Much of a developer's day now goes into directing an AI assistant: asking, reviewing, retrying and correcting. Commits, pull requests and tickets record what came out at the end. They do not show which assistants the team relies on, how much each is used, or where a session went round in circles.

An AI coding analytics platform reads that missing layer. Kite Pulse does it from the records the AI tools already write, so developers keep working as they do today, with no timesheets or manual logging. It is one of several ways to look at engineering. If you mainly need delivery figures from git and tickets, read our overview of how session analytics fits beside git and ticket analytics before choosing.

Building an engineering AI spend report you can defend

An engineering AI spend report needs to be honest about what it measures. Kite Pulse multiplies tokens by each vendor's published list price, so the figure is an estimate. Many developers are on flat subscriptions, which is why the console labels it "not billed spend".

  • What is priced. Claude and Gemini models are priced from list prices. Aider, Cline, Roo Code, Kilo Code and OpenCode report their own cost, and Kite Pulse uses it. Codex, Cursor and Copilot usually show a dash, never $0.
  • Per tool, not one total. Team AI Usage shows cost per tool and does not add it up across tools, because some tools carry no price.
  • Budgets per team or project. Admins set a monthly AI Budget in tokens or estimated US dollars, with alerts at 80% and 100%. A dollar budget adds up the priced tools and reports unpriced tokens separately.
  • Cost per developer is shown to admins only.

For the method in more detail, including how to read the dashes, see our guide to tracking AI coding cost.

A CTO dashboard without another status meeting

A CTO dashboard is only useful if nobody has to compile it. In Kite Pulse, the pages a technology leader opens most are these:

  • Organisation Overview (admin by default): active developers and hours, sessions, commits, project health, working styles, tools and languages.
  • Team Overview: who is online and coding now, active time and sessions today against a typical day, and who needs attention.
  • The Office: everyone's home page, a desk per person grouped by team, with markers for stuck work or plan limits.
  • Company report: any period compared with the one before. Managers and admins can view it; admins can download it as CSV or PDF.
  • Scheduled reports: the Company report emailed daily, weekly or monthly. This needs email set up on the server.

Each manager sees their own reporting line, including indirect reports. An admin sees everyone. The server enforces this, not just the screen.

What Kite Pulse needs from your organisation

Kite Pulse is self-hosted and proprietary. Before you plan a rollout, budget for three things.

What you supply

  • A server you run: one computer, a machine on the team's local network, an Ubuntu server, or your own AWS account.
  • An admin to set up accounts and roles, approve projects, choose which tools are collected and set budgets.
  • Each developer's consent: no session content uploads until they confirm their projects in the Onboarding Wizard, and an approver signs off where required.

What it does not ask for

  • Access to project source files
  • Keystroke logs, screenshots or website history
  • An AI service: it works without one
  • A vendor cloud between you and your data

Session records can include excerpts of code the AI read or wrote. Secrets are masked twice: on the computer before upload, and again on the server. Uploads are encrypted in transit, and each person has a Privacy page that shows what is recorded about them and who can see it.

Scaling AI adoption in engineering: from one team to the organisation

Scaling AI adoption in engineering goes better when the first step is small. A sensible path with Kite Pulse looks like this:

  1. An admin sets up the server, starting with a team pilot on the local network from the same installer used for a single computer.

  2. The admin creates an account for each person, or lets people sign up with a company email domain.

  3. Each developer installs the desktop program and links it to their account with their personal client code, which starts with KP-.

  4. Each developer confirms their projects. Where approval is on, an approver confirms the first project list.

  5. Sessions start to arrive and the team pages fill. When the pilot has answered your questions, move to an Ubuntu server or your own AWS account.

What it will not tell you

  • Your vendor invoice. Cost is an estimate from list prices, and some tools show no price at all.
  • A return on your AI spend. Kite Pulse gives you inputs such as tokens, estimated cost, seat prices and active time. It does not calculate a return figure, and we do not promise one.
  • Delivery metrics. For DORA metrics from git and tickets, a git-based analytics tool fits that job better.
  • Every AI tool. Coverage is the ten tools above. For GitHub Copilot, only Copilot Chat in VS Code is read; inline completions, JetBrains and Copilot CLI are not collected.
  • Plan limits outside Claude Code. Other tools show "Not reported by this tool".

Questions leaders ask

What is the best tool to track AI coding assistant usage for a team?

The right tool depends on how many AI coding assistants your team runs and what you need to see. A vendor's own admin console covers that vendor's tool. Git and ticket analytics cover what was shipped. If developers use several assistants and you want usage, estimated cost per tool and Claude plan limits side by side, look for a tool that reads the assistants' own session history; Kite Pulse does this for ten tools on a server you run.

How can I see AI coding-tool usage across my entire engineering organization?

With Kite Pulse, each developer runs a small desktop program that reads the session history of ten AI coding tools and sends new activity to your own server, after they confirm their projects. An admin then sees everyone on Team AI Usage and Organisation Overview, and each manager sees their own reporting line. Coverage stops at the ten supported tools, and for GitHub Copilot it covers Copilot Chat in VS Code only.

What does a pilot of an AI coding analytics tool look like?

For Kite Pulse, a pilot is usually one team on a local network, set up from the same installer as a single-computer install. An admin sets up the server and creates accounts, each developer installs the desktop program with their personal client code and confirms their projects, and an approver signs off where required. Once sessions arrive, the team pages fill and you can judge the fit before moving to an Ubuntu server or your own AWS account.
