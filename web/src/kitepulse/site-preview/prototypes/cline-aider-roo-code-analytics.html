Cline Analytics for Your Team, with Roo Code, Kilo Code, OpenCode and Aider

Kite Pulse teamUpdated 30 Oct 20267 min read

Cline analytics for a team means reading the session history Cline already keeps on each developer's computer and putting it beside every other AI tool the team uses. Kite Pulse does that for Cline, Roo Code, Kilo Code, OpenCode and Aider: conversations, tool calls, tokens and model names, collected out of the box and sent to a server your team runs. Cost for these five is the figure each tool reports itself, shown per tool and labelled "not billed spend".

Why these five tools are hard to see as a team

Cline, Roo Code, Kilo Code, OpenCode and Aider all do their work on the developer's own computer, and each keeps its history there in its own format. That is fine for the person using the tool. For a lead or a finance owner, it means the record of how the work happened is spread across every laptop, in five different shapes, next to whatever Claude Code, Codex or Cursor sessions the same people run.

A team view needs three things from those records: the same measures for every tool, each session tied to the right person and project, and a clear statement of which figures a tool does not provide. The third matters most when you compare tools, because a missing number is easy to read as a zero.

Tool by tool

Cline analytics

Cline sessions arrive with their conversations, tool calls, tokens and model name, and each session is linked to its project from the folder and repository address. Cline has no login for Kite Pulse to read, so it does not appear on Tool Accounts. The Cline integration page covers setup and the full list of what is read.

Roo Code analytics

Roo Code provides the same set as Cline: conversations, tool calls, tokens, model name and its own reported cost, with failed tool calls recorded. It also has no login on Tool Accounts. See the Roo Code integration page for details.

Kilo Code analytics

Kilo Code matches Cline and Roo Code row for row, so a team that moves between the three sees them in the same columns on Team AI Usage. Details are on the Kilo Code integration page.

OpenCode analytics

OpenCode is the one tool of the five that shows an account on Tool Accounts. That page counts how many separate accounts a tool runs under and marks an account used by more than one person as "Shared". By default only a keyed hash of the account and the email domain are sent, never the address. OpenCode's login store is never sent, and credentials pasted into its chats are masked on your server. Read more on the OpenCode integration page.

Aider analytics

Aider sessions bring conversations, tool calls, tokens, model name and Aider's own reported cost. Failed tool calls are not recorded for Aider, so read its failure figures with that gap in mind. Aider has no login on Tool Accounts. The Aider integration page has the rest.

Why cost comes from the tools' own reports

Kite Pulse prices Claude and Gemini models itself: tokens multiplied by the vendor's published list price, with each price change added as a new dated entry so older sessions keep the price they ran at. Cline, Roo Code, Kilo Code, OpenCode and Aider work differently. Each one records a cost for its own sessions, and Kite Pulse uses that figure.

That has two consequences worth knowing before you compare tools:

  • Different methods sit in different columns. On Team AI Usage, cost is shown per tool and never added up across tools. A list-price estimate for Claude Code and a tool-reported figure for Cline are not totalled into one number.
  • It is still not your invoice. Every cost figure is labelled "not billed spend". A tool-reported cost is as good as the tool's own calculation.

Codex, Cursor and Copilot usually show a dash for cost, never $0, because no price is known for most of those sessions. In AI Budgets, where admins set a monthly budget per team or per project with alerts at 80% and 100%, a dollar budget adds up the priced tools only and reports unpriced tokens separately. These five tools count as priced. Cost per developer is shown to admins only.

What you will not see for these tools

What you see

  • Token use per developer, tool, model, project and day
  • Each tool's own reported cost, per tool
  • Sessions with their conversations and tool calls
  • Failed tool calls, for every tool here except Aider
  • Shared OpenCode accounts on Tool Accounts

What these tools do not provide

  • Plan limits: Plan headroom covers Claude Code only; other tools show "Not reported by this tool"
  • Command exit codes
  • An account for Cline, Roo Code, Kilo Code or Aider
  • Failed tool calls for Aider

If your team needs plan limits for these tools, Kite Pulse does not have them. If you need exact billed spend, your provider's invoice is the right source. And if you want delivery metrics from git and tickets, a git-based analytics tool fits that job better; Kite Pulse covers the AI session itself.

Getting these tools into one view

There is nothing to set up per tool. The same desktop program reads all ten.

  1. Each developer installs the desktop program on Windows or macOS and enters their personal client code, which starts with KP-.

  2. The program finds project folders and their repository addresses, so one repository cloned on several machines counts as one project.

  3. Nothing from a session uploads until the developer confirms their projects in the Onboarding Wizard and, where required, an approver signs off.

  4. Secrets are masked on the computer before upload and again on the server. Session uploads are encrypted and go only to your own server.

On the Tools page an admin has two switches per tool: Session sync, for the conversations, and Token consumption, for counts only. With Session sync off and Token consumption on, the program counts tokens on the computer and sends only the numbers.

Kite Pulse

If a team wants usage figures for Aider or Kilo Code without uploading any conversation, counts-only mode does that per tool. It does not open project source files, though session records can include excerpts of code the AI read or wrote, with secrets masked.

Questions about these integrations

Which AI coding tools does Kite Pulse support?

Ten, all collected out of the box: Claude Code, Codex, Gemini CLI, Cursor, GitHub Copilot Chat in VS Code, Cline, Roo Code, Kilo Code, OpenCode and Aider. An admin can switch any of them off, or collect token counts only. Copilot inline completions, JetBrains and Copilot CLI are not collected.

Are Kite Pulse cost figures exact?

No. Cost is an estimate, labelled "not billed spend". Claude and Gemini models are priced from the vendor's published list price; Aider, Cline, Roo Code, Kilo Code and OpenCode use the cost the tool reports itself. Cost is shown per tool and never added up across tools, so use it to guide decisions and keep your provider's invoice as the record of what you paid.

How accurate are AI coding cost estimates?

They are only as accurate as their inputs. An estimate built from token counts and list prices leaves out discounts and flat subscriptions, and a figure a tool reports itself depends on how that tool calculated it. Treat either as a guide to where spend is going, compare it with your invoices, and keep estimates from different methods in separate columns rather than adding them together.
