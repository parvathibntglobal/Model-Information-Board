How Kite Pulse tracks AI coding tool usage

      
A small background program on each developer's computer picks up the session history the AI coding assistants already keep, strips out secrets, and sends it to your team's own Kite Pulse server. It covers ten tools: Claude Code, Codex, Gemini CLI, Cursor, GitHub Copilot, Cline, Roo Code, Kilo Code, OpenCode and Aider. That includes agentic coding sessions, where an assistant runs commands and edits files on its own.

AI coding analytics: questions

    

      
Can companies track AI usage?
Yes. Companies track AI coding tool usage through each vendor's admin console, through API usage reports, and through tools that read the session history AI coding assistants keep on each developer's computer. What they can see depends on the method: vendor consoles cover one tool each, and session history covers every tool it supports in one view.

      
How do companies track AI coding tool usage?
Most start with vendor admin consoles, which show seats and some usage for one tool at a time. Teams that use several tools add a spreadsheet of exports, or a tool that collects sessions across all of them and splits usage by person, team, project and period. Whatever the method, tell developers what is collected and why before you start.

      
How many developers on my team actively use AI coding assistants?
Define "active" first, for example at least one AI coding session in the period, then count people in scope who meet it, across every tool. Counting per tool overstates adoption when one person uses three tools, and understates it when people use a tool your consoles do not cover. Account for leave, or a week off looks like non-adoption.

      
How do I measure AI coding tool adoption on my team?
Track three things per period: the share of people in scope who used any AI coding tool, which tools and how many accounts each runs under, and where the work happened by project. Split by team and by start date to see how quickly new developers adopt. Adoption shows use, not value; measure delivery and quality separately.

      
How do I compare AI tool usage across Cursor, Claude Code and Copilot?
Compare the same measures for each tool over the same period: active people, sessions, tokens where the tool reports them, and projects. Vendor consoles define these differently, so a comparison built from three consoles mixes three definitions. Collecting sessions from all tools in one place gives one definition for every tool.

      
How do I compare AI coding tool usage across teams?
Record which team each person belonged to and when, then split the same usage measures by team for the same period. Without dated team membership, a re-organisation moves usage between teams after the fact. Compare teams, never individuals, and read usage alongside the kind of work each team does.

      
How do I find out which projects my team uses AI on the most?
Tie each AI session to the repository it ran in, then add up sessions or tokens per repository and map repositories to projects. Watch for the same repository cloned under different folder names on different machines, which splits one project into two.

      
How can I see AI coding tool usage across my entire engineering organisation?
You need one collection method that covers every tool your developers use, plus a record of who belongs to which team. Kite Pulse gives admins a Company Overview with active people and hours, project health and tool use across the organisation, and managers see their own reporting line.

      
Can I track AI coding tool usage over days, weeks and months?
Yes. Keep the period fixed when you compare, because usage swings with releases, holidays and on-call rotas. In Kite Pulse, Team AI Usage shows tokens per developer, per tool and per period, and Reports produce a summary for any period as a spreadsheet, or by email on a schedule.

      
How can I track which AI models my team uses?
Start with the usage reports of the model providers and the AI tools' admin consoles, which often break usage down by model for API-billed plans. Subscription plans show less. Model mix matters for cost and for plan limits, because some plans cap a model's weekly use separately.

      
Which developers use AI coding assistants the most, and which not at all?
You can see it, but use it to offer help, not to rank people. Heavy use may mean a large task or a tool stuck in a loop; no use may mean leave, a role that does not code, or a tool your collection does not cover. Check those before drawing a conclusion, and talk to the person rather than about them.

      
Which AI coding tool is my team most productive with?
Usage data alone cannot tell you. A tool can be used most because it is the default, not because it helps most. To answer it, compare delivery and quality metrics for work done with each tool over the same period, with a baseline.

      
What metrics should I use to measure AI-assisted development?
For usage: active people, sessions, tokens and estimated cost per tool, team and project. For results: lead time, change failure rate and rework against a baseline. For experience: where AI sessions get stuck, such as repeated failing commands and abandoned approaches. Usage metrics describe adoption; only the other two describe value.

      
What is the best dashboard for AI-assisted engineering teams?
The one that covers every AI tool your team uses, splits usage by person, team, project and period, shows cost and plan limits, and is clear with developers about what it collects. Check where the data is stored, whether it reads source code, and whether it ranks individuals before you choose.
