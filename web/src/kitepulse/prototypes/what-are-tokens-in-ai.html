What Are Tokens in AI and How Much Do They Cost? A Plain Guide for Non-Engineers

A token is a small piece of text, often a short word or part of a word, and it is the unit AI models use to count everything they read and everything they write. So when someone asks what are tokens in AI and how much do they cost, the answer has two parts. With pay-as-you-go access, every token has a list price. On a flat plan such as Claude Pro, tokens do not add to the bill; they use up a usage limit that resets over time.

What are tokens in AI, in simple terms

AI models do not read words the way people do. Before a model sees any text, the text is cut into tokens: short words stay whole, longer or rarer words are split into pieces, and punctuation, spaces and symbols become tokens of their own. Computer code splits into tokens too, brackets and all.

Everything is counted: the developer's question, every file the assistant opens, the instructions the tool adds behind the scenes, and every line the model writes back. Text going into the model is input; text the model produces is output. Those two counts are the basis of every AI price list and every usage limit.

A useful mental model is a taxi meter that runs on text rather than distance. It does not care whether the text was a good question or a wasted one.

What an AI coding session is, and why the tools keep its history

A session is one working conversation between a developer and an AI coding assistant. The developer describes a task. The assistant reads the relevant files, may run commands or tests, proposes changes, and replies. The developer reacts, and the loop continues until the task is done or set aside.

Modern assistants increasingly take several of those steps on their own, which is what people mean by agentic coding, where the assistant plans and carries out multi-step work. Each step is another round of reading and writing, so each step uses more tokens.

AI coding tools save each session as a file on the developer's own computer, so a conversation can be scrolled back or picked up again later. That history also records which model answered and how many tokens each turn used, which is what makes token use measurable after the fact.

Why tokens drive the cost of AI coding tools

A model does not remember a conversation between turns. To answer the next message, the tool sends it the conversation so far, plus anything new. So a long session gets more expensive per turn as it goes: the tenth question carries the nine before it.

That explains most of the surprises finance teams meet:

  • Long sessions grow. A question costs more late in a long conversation than in a fresh one.
  • Reading counts. Files an assistant opens are input, even if the reply is short.
  • Agents multiply steps. One request can become many turns, and sub-agents run conversations of their own.
  • Models differ. Each model has its own price per token, so the same work costs a different amount on a different model.
Illustrative example, not a customer case

Two developers each spend an afternoon fixing a bug.

  1. The first asks a few short questions in separate, fresh conversations and edits the code by hand.
  2. The second hands the whole bug to an agent, which reads a large part of the project, runs the tests repeatedly and revises its fix several times in one long session.

Both fixed one bug, yet the second afternoon can use many times the tokens. The count describes the way of working more than the person.

This is why the cost of AI coding tools is rarely just the seat price on the order form. Seats are predictable; token use is not. For how seat prices compare across vendors, see our AI coding assistant pricing comparison.

How are AI tokens priced?

Vendors that sell access by the token publish a price per million tokens, per model, and they price different kinds of tokens differently. On Anthropic's published prices for Claude, the kinds are:

Kind of tokenWhat it isPrice compared with input
InputText the model reads: the question, the conversation so far, filesThe base price
OutputText the model writesHigher
Cache writeInput saved so it can be reused on later turnsHigher than base input
Cache readSaved input reused instead of being processed againWell below base input

Prices change with the model and over time, so read them on the vendor's own pricing page when you need them.

Claude Code cache tokens

Because every turn resends the conversation so far, Claude Code uses caching: the unchanged start of a conversation is stored once and then read back cheaply on the next turns. That is why a Claude Code usage report shows Claude Code cache tokens beside input and output, often as the largest numbers on it. Adding all kinds together at the input price would overstate the cost.

What is a Claude plan limit?

Many developers do not pay per token at all. They are on a flat monthly subscription such as Claude Pro or Claude Max, which comes with usage limits instead of a meter. Put simply, Claude Pro plan limits cap how much work the plan covers in a window of time.

According to Anthropic's help centre, Pro and Max plans have a five-hour session limit and a weekly limit, and some plans add a separate weekly limit for a particular model. The limits are shared across the Claude app and Claude Code, so a developer's chat use and coding use draw on the same allowance. The tokens behind each request are what use it up, which is why a long agent session can reach a Claude usage limit in an afternoon while light use never comes close.

When a limit is reached, the developer has three options: wait for the window to reset, turn on paid extra usage, or switch to API access billed per token, which is charged separately from the plan. For the details of each window and how to make the allowance last, read our guide to Claude Code usage limits.

Other vendors set their own AI plan limits, so a Claude window says nothing about a Codex or Cursor plan.

List price or flat plan: two ways to pay for the same tokens

This matters most to finance: the same session can be paid for in two ways, and the tokens mean something different in each.

Pay-as-you-go (API)Flat plan with limits
What a token costsIts list priceNothing extra, up to the limit
What the bill showsUsage, so it varies month to monthThe seat price, so it stays flat
What runs outBudgetThe window, until it resets
The riskA surprise invoiceLost working time at the limit, or extra usage charges

Two practical consequences follow. First, on a flat plan, multiplying tokens by the list price gives you the value of the work at pay-as-you-go rates, which is useful for comparing plans, and is not money you spent. Second, a team on flat plans can still have a cost problem, but it shows up as people stopped by limits rather than as a larger invoice. Questions about tokens and Claude usage limits

how is token usage calculated in ai

The model splits all text into tokens and counts them in two directions: input tokens for everything it reads, and output tokens for everything it writes. In a coding session the input includes the whole conversation so far, the files the assistant opened and the results of commands it ran, so each new turn usually reads more than the last. Where a tool uses caching, part of that input is counted separately as cache writes and cache reads. The tool records these counts in its session history after every turn.

how do claude code usage limits work

On a Claude Pro or Max plan, Claude Code draws on the same usage limits as the Claude app, according to Anthropic's help centre. There is a five-hour session limit and a weekly limit, and some plans add a separate weekly limit for a particular model. When a limit is used up, the developer waits for it to reset, turns on paid extra usage, or switches to API access billed per token.
