Who is close to a Claude limit right now?

Each person sees their own limits; a lead hears about them when someone is already blocked. Plan headroom is the Claude Code limit dashboard for the whole team, on the Plan headroom tab of Team AI Usage.

  • Three windows per developer: the 5-hour window, the weekly window and each model's weekly window.
  • Worst first, so the people about to run out sit at the top.
  • "Near" means 80% or more; "at limit" means 100%.
  • Each figure names the Claude account it belongs to. Managers see their own reporting line; admins see everyone.

How fresh is each reading, and where does it come from?

  • Figures come from the usage data Claude Code saves on the developer's computer. No login or password is read.
  • By default a reading is as fresh as the last time Claude Code saved it.
  • An optional background refresh keeps figures current without using any tokens. It is off until an admin switches it on, needs Kite Pulse app 0.4.2 or later, runs hourly by default (every 5 minutes to every 6 hours), and each developer can turn it off.
  • Old readings are flagged as stale with the reason, such as the refresh being off, an old app, the developer opting out, or Claude Code sitting idle. They are never hidden.

Who ran out last month, and how often?

The Plan usage report is the history behind the live list: a month or a date range, per developer and per Claude account, as a Claude plan usage report in Excel when you need to export Claude usage data.

  • Weekly peaks, weeks at 80% or more, weeks at the limit, 5-hour windows at the limit, and per-model peaks.
  • Downloads as Excel, for admins by default.
  • History starts when recording began.

Questions about Claude Code limits for teams

How do I know which developers are close to their Claude limit?

Use one list of the whole team, sorted by how much of each Claude plan window is used. In Kite Pulse that is the Plan headroom tab of Team AI Usage: the 5-hour, weekly and per-model weekly windows per developer, worst first, with 80% marked near and 100% at limit.

How close am I to my Claude Code limit?

With Kite Pulse, your own Claude plan usage is on your Workspace page. For how the windows work, see the Claude Code usage limits guide.

How do I plan sprints around AI plan limits?

Check who is near a weekly limit before handing out the heaviest AI work, and use past weekly peaks to see who runs short most often. The sprint planning article walks through a full routine.

Which Claude plan does my engineering team need?

Kite Pulse does not recommend a plan. It gives you evidence: the Plan usage report shows how many weeks each developer and Claude account reached 80% or more, and how many hit the limit. Frequent limits argue for a larger plan; low peaks argue against one.

Does Plan headroom cover Codex, Cursor or other AI tools?

No. Plan headroom covers Claude Code only. The other nine tools Kite Pulse reads show Not reported by this tool.

How fresh are the plan figures?

By default, as fresh as the last time Claude Code saved them. An optional background refresh, switched on by an admin, keeps them current without using any tokens. Old readings are flagged as stale, never hidden.
