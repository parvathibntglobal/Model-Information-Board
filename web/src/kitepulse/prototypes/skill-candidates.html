Skill Candidates: a Claude Code skills generator built from your team's repeated work

The steps your team types again and again, turned into draft skills a person can edit, approve or reject.

Skill Candidates is a rule-based Claude Code skills generator: it finds workflows that repeat across your team's sessions and turns each one into a draft Claude Code skill, for a person to approve or reject. It uses no AI model and needs no AI key.

Session Graph, which groups sessions that look alike, and Capability Map, which describes each project in product terms, use no AI model either. Knowledge Records are the one part here that needs AI labelling, which stays off until an admin sets it up.

Turn repeated workflows into Claude Code skills

When several people walk Claude Code through the same steps in the same project, that is a skill nobody has written yet. Skill Candidates, under Insights › Knowledge, finds that repeated work and drafts the skill for you.

  • Each candidate shows how often the work repeated, in how many sessions and by how many developers. It never shows who.
  • Each comes with a draft SKILL.md to edit, then approve or reject.
  • Built by rules on your own server. No AI model and no AI key.
  • Admins by default; an admin can grant it to other roles on Roles & Permissions.

Generate a Claude Code skill from evidence, not a blank page

      
The usual way to create a Claude Code skill is to guess which workflow deserves one and write it from memory. Skill Candidates starts from what sessions actually did, so you build Claude Code skills for work that already repeats, and you can see how much it repeats before you spend time on it.

      
    
        
  • The draft is a starting point. A person edits it, then approves or rejects it.
    • 
        
  • Rejecting is a normal outcome: not every repeated workflow should be a skill.
    • 
        
  • To see which Claude Code agent features sessions already use, such as sub-agents, background commands, plan mode, worktrees and MCP tools, open the Agent features tab on Team AI Usage, by session and developer.

Questions about Skill Candidates

    

      
Does Skill Candidates use an AI model to write the skills?
No. Draft skills are built by rules from repeated workflows, on your own server, with no AI model and no AI key. Session Graph and Capability Map use no AI model either.

      
Does a draft skill reach the team on its own?
No. Every candidate is a draft for a person to edit, then approve or reject. Kite Pulse proposes the skill; a person decides.

      
Does Skill Candidates show who repeated the workflow?
No. It shows how often the work repeated, in how many sessions and by how many developers, never which developers.

      
What do Knowledge Records need before they appear?
AI labelling, which is opt-in. An admin adds an OpenRouter key and a monthly budget, switches labelling on, and approves and runs the knowledge label list. Records then appear as proposed. Without that, the page stays empty and everything else on this page still works.

      
How do I find repeated prompts in Claude Code for myself?
Your private prompt statistics in My Scorecard and Insights show your most repeated prompt. Only you see them; the server removes them for everyone else.
