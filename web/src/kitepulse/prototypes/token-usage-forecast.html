Token Usage Forecast: Where Your Team's AI Use Is Heading

Kite Pulse teamUpdated 30 Oct 20267 min read

A token usage forecast takes your team's recent daily token use and projects it forward, so you can see where AI use is heading before the month closes. The simplest version that works: average the last 14 days of tokens per day, multiply by the next 30 days, and mark any day that used at least twice the average. Keep it in tokens first, then compare it with a monthly token budget.

Why forecast tokens at all

Most teams find out how much AI they used when the month ends. By then the only decision left is whether to be surprised. A forecast moves that moment forward: on day ten you can already say whether the month is on pace, ahead or behind, and act while there is still time to change something.

It also changes the conversation. "We used a lot of tokens" is hard to act on. "At this pace we reach the monthly budget around the 24th, and one heavy day last week accounts for most of the gap" gives a manager and finance something concrete to discuss.

Forecast tokens, not money

Money feels like the natural unit, and it is the wrong one to start with. A dollar figure for AI coding tools is usually an estimate: tokens multiplied by a vendor's published list price. Many developers are on flat subscriptions, so that estimate is not what the company is billed. Some tools do not publish a price for every model at all, and a forecast built on missing prices quietly undercounts.

Tokens have neither problem. Every AI coding tool records them, the count does not change when a price list does, and a token forecast can be compared directly with a budget set in tokens. Once the token pace is clear, convert it to an estimated cost per tool where a price is known, and keep the unpriced tokens visible beside it rather than leaving them out. Our guide to tracking AI coding cost from list prices covers that second step.

One caution when comparing tools: they do not all count the same tokens. Cursor and GitHub Copilot Chat in VS Code record input and output tokens only, while tools such as Claude Code report the full set. Forecast each tool on its own line rather than as one blended total.

Token usage prediction in five steps

This is a straight-line forecast. It assumes the next month will look like the recent past, which is often true for a stable team and is easy to check.

  1. Collect daily token totals for the last 14 days. Two full weeks include two sets of weekends, so quiet days and busy days are weighted the way they really fall. Fewer days and a single unusual afternoon can swing the result.

  2. Work out the average per day. Add the 14 totals and divide by 14. Count calendar days, weekends included, because the days you project forward will include weekends too.

  3. Project the outlook. Multiply the daily average by 30 for a rolling 30-day outlook, or by the days left in the month if you are checking a monthly budget, then add what is already used this month.

  4. Mark heavy days. Flag any day that used at least twice the average. A heavy day is not a problem in itself; it is a question. A large migration, a new agent workflow or a runaway retry loop all look the same in the totals.

  5. Compare with the budget and recalculate weekly. Set the outlook against the monthly token budget and its warning line. Repeat each week, because a forecast that is a month old describes a different team.

That one day moves the forecast by roughly 13 million tokens, which is why heavy days are worth a look before the total is trusted.

Now set it against an example budget of 120 million tokens a month, with a warning at 80%, which is 96 million. An outlook of about 103 million passes the warning line but stays under the budget. If Tuesday was a one-off migration, the team is comfortably on pace. If it was a new workflow the team plans to keep, the real pace is higher than the average suggests, and the budget conversation should happen now.

How to predict Claude Code usage against plan limits

A team on Claude plans has a second question that a monthly token total cannot answer: will someone run out of plan in the middle of a task? Claude plan limits are measured in windows, so the useful prediction is about how full each window gets. There is a 5-hour window, a weekly window and a weekly window for each model.

The best predictor is a person's own history. Look at their weekly peaks over the last month or two. If someone's weekly window reached 80% or more in most recent weeks, expect it again unless their work changes, and plan large tasks for the start of a new window rather than the end. A team-wide token forecast can look calm while one heavy user is at 100% of a weekly window, so check both.

Our page on Claude plan headroom explains the windows in more detail and how to see who is close to a limit.

Token usage monitoring: what to watch between forecasts

A forecast is a weekly exercise. Token usage monitoring is what keeps it honest between those checks. Three habits cover most of it:

  • Look at daily totals by tool, model and project, so a jump can be traced to a cause instead of argued about.
  • Set a monthly budget in tokens with a warning line, so the first signal arrives at 80% rather than at the limit.
  • Write down the reason for each heavy day once it is known. After a few months those notes tell you which spikes are planned work and which are worth fixing.

Know the limits of the method too. A straight-line forecast cannot see a launch next week, a new hire on Monday or a move to a larger model. When you know the work is about to change, adjust the forecast by hand and say so beside it.

Questions about token usage forecasts

How accurate is a token usage forecast?

A straight-line forecast is only as good as the assumption that the next month looks like the last two weeks. It is close enough to spot a budget problem early, and it is wrong whenever the work changes: a launch, a new hire, a holiday or a switch to a different model. Treat it as a pace to check against, recalculate it every week, and look at heavy days before you trust the total.

Should a token usage forecast be in tokens or dollars?

Start with tokens. Every AI coding tool records them, while a dollar figure is an estimate from list prices that many tools cannot supply and that is not what a team on flat subscriptions is billed. Convert to an estimated dollar figure afterwards, per tool, and only for tools with a known price.

How do I predict Claude Code usage against plan limits?

Plan limits are measured in windows, so look at how full each window gets rather than at a monthly token total. For Claude Code that means the 5-hour window, the weekly window and each model's weekly window. History helps most: if a person's weekly window reached 80% or more in most recent weeks, expect it again next week unless their work changes.
