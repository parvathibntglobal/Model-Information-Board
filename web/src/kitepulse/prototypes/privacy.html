Privacy-first developer analytics for AI coding

Kite Pulse is privacy-first developer analytics: it reads the session records ten AI coding tools already keep, masks secrets, and sends them only to a server your team runs. It does not open a project's source files, log keystrokes, take screenshots or track websites. Session records can include excerpts of code the AI read or wrote, and nothing from a session uploads until the developer confirms their projects.

Privacy preserving analytics, step by step

In privacy preserving analytics the order of events is part of the safeguard. Each step happens before the next can.

  1. Folder listDetected project folders are sent for the developer to review.
  2. ConsentThe developer confirms projects. An approver signs off where required.
  3. Mask36 credential patterns masked on the computer. If masking fails, that part is not sent.
  4. EncryptSession uploads encrypted before they leave; status records over HTTPS.
  5. Your serverNo built-in server address, no vendor cloud.
  6. Mask againThe server masks secrets again before storage.

Cursor and OpenCode chat text is masked on the server only; their login stores are never sent. More in AI secret scanning.

Track token usage without collecting prompts

Each tool has two switches on Tools: Session sync (the conversations) and Token consumption (counts only). With Session sync off and Token consumption on, the program counts tokens on the computer and sends only the numbers, never the conversation.

Controls for admins

  • Tools. All ten tools are on in a new install; switch any off, or collect counts only.
  • Projects an admin switches off are not read at all. Onboarding Approvals is on by default.
  • Optional reads stay off until turned on under Settings › Retention › Kite Pulse app reads.
  • Roles & Permissions. A view and edit grid per page for each role.
  • AI labelling is opt-in. If turned on, scrubbed text goes to the AI provider through OpenRouter (default policy: zero data retention), logged in the AI Call Log.
  • Retention. Set how long data is kept; deletion applies once the server operator enables it.
  • Export or erase one person's data; both are recorded in the Audit Log. More on the security page.

What Kite Pulse does not do

Does not

  • Open project source files
  • Log keystrokes or take screenshots
  • Track websites
  • Send data to a vendor cloud
  • Send tool account email addresses by default
  • Need an AI service to work

Limits to know

  • Erasing a person anonymises the account, deletes raw activity records and destroys their encryption keys. Plain-text working copies of their sessions stay on the server.
  • Stored sessions are scrubbed but not encrypted by the app. Protection of stored data comes from your server's own disk encryption, or S3 on AWS.

Questions about privacy

Does an AI coding analytics tool read or store our source code?

Kite Pulse does not open a project's source files. It reads the AI tools' session records, folder names and repository addresses. Session records can include excerpts of code the AI read or wrote, so with session sync on those excerpts are stored on your own server, secrets masked.

How do I track AI coding usage without monitoring keystrokes?

Read the session history the AI coding tools already keep, instead of watching the person. Kite Pulse's desktop program does exactly that: it does not log keystrokes, take screenshots, track websites or open a project's source files. For the least data, collect token counts only.

Can I track AI coding usage without reading developers' prompts?

Yes. Turn Session sync off and Token consumption on for a tool. The desktop program then counts tokens on the computer and sends only the numbers, never the conversation.

Can managers see developers' AI prompts?

Yes, within their own reporting line: managers see activity figures and session details, so with session sync on they can read those sessions. They never see a developer's private prompt statistics. Admins can change what each role sees on Roles & Permissions.

How are secrets and credentials handled before upload?

The desktop program masks 36 credential patterns before upload, such as cloud and AI provider keys, GitHub and GitLab tokens and private keys. If masking fails, that part is not sent. The server masks again before storage. Cursor and OpenCode chat text is masked on the server only.

Where is AI coding usage data stored and who can access it?

On the Kite Pulse server your team runs, in PostgreSQL and on local disk or Amazon S3, with no vendor cloud in between. Developers see their own pages, managers their reporting line and admins everyone, enforced by the server.

Is AI coding analytics GDPR compliant and can we erase a person's data?

Kite Pulse holds no certification, and compliance depends on how you run it, so check with your privacy officer. An admin can export or erase one person's data. Erasing anonymises the account, deletes their raw activity records and destroys their encryption keys; plain-text working copies of their sessions stay on the server.
