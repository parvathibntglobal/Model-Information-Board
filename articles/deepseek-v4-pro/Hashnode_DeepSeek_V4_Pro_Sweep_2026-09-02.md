## 2. What search Hashnode actually offers — the constraint that shaped this sweep

The brief assumed a free GraphQL API at `gql.hashnode.com`. **That is no longer true**, and the difference changed the method, so it is reported first.

| Probe | Result |
|---|---|
| `POST https://gql.hashnode.com` | **301** → `https://hashnode.com/announcements/graphql-api` |
| `POST https://gql.hashnode.com/graphql` | **522** Cloudflare — no origin behind it |
| `POST https://api.hashnode.com/graphql` | **421** Misdirected Request (the retired endpoint) |
| `GET https://hashnode.com/search?q=…` | **200**, but **zero** results server-rendered — the query string is echoed back and results load client-side from `/api/` |
| `GET https://hashnode.com/robots.txt` | `Disallow: /api/` |
| `GET https://hashnode.com/tag/<tag>` | **200**, **10 posts server-rendered** with full metadata |
| `GET https://hashnode.com/tag/<tag>?page=2` | **200**, returns the **same 10** — no pagination without `/api/` |

Hashnode's own changelog, dated **13 May 2026**, states it plainly:

> "🔌 We're retiring free GraphQL API access. Every API request, queries and mutations, now requires a Pro plan on your publication. […] **Reads used to be free. They aren't anymore.**"

So: **there is no global full-text search available, no `searchPostsOfPublication`, and no free API of any kind.** Answering the brief's question directly — the shape had to be *find posts by tag, then match locally*, and even that is capped.

### The route actually used

Two surfaces, both public HTML on robots-allowed paths. **`/api/` was never called.**

1. **Tag harvest** — `hashnode.com/tag/{ai, machine-learning, llm, deepseek, artificial-intelligence, programming}`. Post objects are embedded in the server-rendered Next.js payload (title, slug, author, username, `publishedAt`, `readTimeInMinutes`, `upvotes`, `responseCount`, `views`, `blogUrl`). **47 distinct posts** across the six tags; **10** mentioned DeepSeek, **7** matched DeepSeek + V4 locally.
2. **External search engine** → individual public post pages, fetched and parsed for JSON-LD, canonical URL, and body text. This recovered older posts the tag pages could not reach (tag pages show only the 10 most recent).

Requests issued: **6** tag pages, **12** post pages, **~14** endpoint/robots probes. Rate-limited to roughly one request per second. **Nothing was refused** beyond the API results in the table above.

### What this retrieval cannot see

- Tag pages return **only the 10 most recent posts** per tag and will not page. Anything older than the current top-10 is invisible to route 1 and reachable only if a search engine happens to surface it.
- Hashnode's own search index is unreachable, so a post using the model name in its body but not in title/brief/slug, and not ranked by an external engine, is missed entirely.
- **This sample is retrieval-shaped, and doubly so:** route 1 is *recency*-shaped, route 2 is *search-engine-ranking*-shaped. Neither is a random or complete draw from Hashnode. Absence of a post here is weak evidence it does not exist; presence is solid.

## 6. Platform-specific observations

**The tutorial skew is real but reads differently here.** Of 11 in-window posts, 3 are tutorials or setup guides. What is striking is not that tutorials dominate, but that **the non-tutorials are almost all price analysis** — the DeepSeek V4 Pro conversation on Hashnode is about *what it costs*, not *how good it is*. Only one post (`computeleap`) reports capability numbers at all, and it borrows every one of them.

**Generated-or-near-generated content: present, but not where expected.** Two specific signals:

- `softreviewed.hashnode.dev` carries a post dated **30 September 2025** describing DeepSeek V4's "1M Token Context Window and GRPO Reasoning" — roughly **seven months before V4 was released** (24 April 2026). A dated-in-the-past post describing an unreleased model's features is not a small error. Author bio: founder of a software-review site with "over a decade of experience in digital marketing." Excluded from counts.
- `postal-ai.hashnode.dev` publishes an "API Guide" for **DeepSeek V4.1**, opening by conceding "it is not an officially released model yet." Content pegged to a version string that does not exist is an SEO shape, whatever produced it.

**The four-posts-one-author pattern.** `@mr-manushukla` accounts for **4 of 11** in-window posts (36%), all published **21–24 August 2026**, all 12–14 minute reads, all cross-posted from `ecorpit.com`. A four-post burst in four days is a publishing cadence worth noting. In fairness to the content: these are the **best-sourced posts in the sample**, each carrying a References section and citing dated vendor changelogs and pricing pages. High volume and real sourcing are not mutually exclusive, and here they co-occur.

**Cross-posting is the norm, not the exception, among the substantive posts.** 5 of 11 are cross-posted — but that is **5 of the 6** posts with the most artifacts. Every one of the genuinely substantive items is the same document living on a company domain. If `ecorpit.com` and `computeleap.com` are also in a reading list, this sweep has surfaced almost nothing new.
